# Telegram bot: quick user guide

The bot is designed so routine seller actions are available from inline buttons.
Send `/start` to resume required setup or open the main menu. Use
`❓ Помощь и команды` at any time to open the in-bot guide.

## Main actions

- `💵 Прибыль за период` — account Period Profit and profit for a selected SKU;
- `💰 Себестоимость` — guided current seller-cost update;
- `💰 Юнит-экономика товаров` — per-product economics;
- `🎯 Решения по товарам` — read-only product recommendations;
- `↩️ Расходы на возвраты` — return finance impact;
- `🧠 Память` — seller facts explicitly saved for the assistant;
- `❓ Помощь и команды` — complete command memo and valid phrase examples;
- `ℹ️ О боте / версия` — revision captured by the running process and its UTC start time.

If no validated build revision is available, the bot labels itself as a local build
with no version set. The version display is read-only and reflects the running
process; updating files on disk does not change it until that process is restarted.

## Аналитика прибыли магазина

После отчёта `Прибыль за период` нажмите `📊 Аналитика периода`. Там доступны
сравнение с предыдущим равным периодом, разбор подтверждённых изменений прибыли,
вклад однозначно сопоставленных товаров и полнота данных. Кнопка `↩️ К расчёту`
возвращает исходный отчёт; из вклада SKU можно открыть уже существующий выбор
товара.

Все экраны показывают тот же расчёт и ту же выбранную пару периодов. Открытие
деталей не обновляет данные Ozon. Снимок доступен 10 минут и привязан к магазину
и пользователю; после истечения срока нужно заново запросить прибыль. Если
сопоставление периодов или SKU неполное, бот явно сообщает об этом и не считает
отсутствующие значения нулевыми.

В отчёте периода доступны `⬇️ CSV` и `⬇️ JSON`. Для обзора товаров, пакетного
плана и чувствительности отдельные кнопки выгружают весь открытый снимок и его
текущий scope, а не только видимую страницу. Открытие и скачивание используют
уже рассчитанные данные; обновление источников выполняется только отдельным
действием. Плановые выгрузки описывают сценарий и не меняют цену в Ozon.

На экране полноты данных выберите \`❓ Почему расчёт неполный?\`, чтобы увидеть
подтверждённые причины неполноты, состояние источников и счётчики операции.
Экран использует тот же снимок, не обновляет Ozon автоматически и предлагает
доступные действия, например заполнить себестоимость, проверить SKU или явно
пересчитать отчёт.

Кнопка «📦 Сохранить диагностику» создаёт обезличенный JSON для поддержки.
В нём остаются только коды, типы полей, счётчики, период и псевдонимы SKU;
суммы, названия товаров, исходные идентификаторы и ответы API не добавляются.
Файл доступен только владельцу исходного отчёта, в том же магазине и пока не
истёк снимок. Экспорт использует кэш и не повторяет запросы к Ozon.
Диагностический JSON также содержит revision и время старта процесса, если они
прошли проверку формата.

## Локальный запуск и остановка (Windows)

Для обычного видимого запуска выполните `.\start_bot.ps1` из папки проекта.
Фоновый экземпляр запускается отдельной командой:

```powershell
.\start_bot.ps1 -Background
```

Проверка состояния и штатная остановка доступны из любого окна PowerShell в папке проекта:

```powershell
.\status_bot.ps1
```

```powershell
.\stop_bot.ps1
```

`RUNNING` означает, что Telegram polling и обработка обновлений запущены. Во время
подготовки может отображаться `STARTING`. Остановка ждёт не более 15 секунд и не
завершает Python-процессы принудительно. Один токен использует только один
экземпляр polling; другой bot token может работать независимо.

## Планирование цены SKU

В существующем калькуляторе выберите товар и задайте недостающие допущения
(например, рекламу). Кнопка `Цена для целевой маржи` принимает процент от 0 до
100 и показывает проверенный ориентир безубыточности и цену для цели. Кнопка
`Сравнить цены` принимает от двух до пяти разных цен через `;` или с новой
строки; например, `499,90; 549,90; 599,90`. Если ранее в этом сценарии была
введена целевая маржа, таблица показывает, достигнута ли она каждой ценой.
Кнопка под строкой подставляет её цену только в текущий расчёт; кнопка в
результате цели подставляет цену, прошедшую проверку целевой маржи.

Это локальный сценарий одной успешной продажи FBO: цена Ozon не меняется,
себестоимость и расходы не сохраняются. Неизвестные обязательные расходы нужно
задать отдельно; бот не считает их нулём. Комиссия может измениться при новой
цене; FBS, постоянные расходы, хранение и возвраты не моделируются.

Кнопка `Сколько можно тратить на рекламу?` попросит целевую маржу и покажет
максимальную долю рекламы от цены продавца для безубыточности и этой цели,
а также текущий запас в процентных пунктах и рублях на единицу. При явном
подтверждении предел можно подставить в текущие локальные допущения; перед этим
бот повторно рассчитывает прибыль. Кампании Ozon не меняются. В пакетном плане
предел доступен отдельно для каждой строки. В карточке сохранённого плана он
показывается только по историческим допущениям; для изменения сначала откройте
план как временный сценарий и проверьте актуальность источников.

Сохраните нужный сценарий кнопкой `💾 Сохранить план` и задайте название.
В `📚 Мои планы` доступны список с постраничной навигацией, историческая
карточка, история версий, копирование, переименование, архив и восстановление.
Просмотр сохранённой карточки не запрашивает Ozon и не пересчитывает старые
допущения как актуальные. `Продолжить по сохранённым допущениям` открывает новый
временный сценарий с пометкой об историческом источнике.

Чтобы получить актуальную оценку, выберите `Обновить источники`. Ручные значения
переносятся только для той же точной карточки товара; после сравнения можно
отдельно сохранить новую ревизию в исходный план или сохранить копию. Обновление
не меняет исходную ревизию автоматически. Удаление плана требует отдельного
подтверждения. Все операции ограничены текущим пользователем и магазином.

В сохранённом плане кнопка `План объёма продаж` позволяет задать период и
количество успешных продаж для каждого SKU. Введите `0` только если продаж
действительно не было; отдельной кнопкой можно оставить количество неизвестным.
Затем перечислите дополнительные фиксированные расходы за период или введите
`0`, чтобы явно подтвердить, что расходов нет. Предпросмотр показывает по SKU
количество, цену продавца, выручку, себестоимость, комиссию, рекламу, fees и
вклад до налога. Расходы за период вычитаются один раз, налог считается одним
вызовом действующей налоговой политики для группы. Если количество или расчёт
по строке неизвестны, бот показывает подтверждённый subtotal без итоговой
прибыли и маржи набора. Сумма индивидуальных рекламных лимитов, если доступна,
не является оптимизацией и не гарантирует целевую маржу группы. Сохранение
добавляет новую ревизию локального плана; Ozon и фактический учёт не меняются.

В плане объёма ставка кросс-докинга берётся из замороженного 56-дневного
источника для SKU и умножается на плановое количество успешных продаж. Исторический
знаменатель этой ставки — фактически принятые единицы поставок, а не продажи.
Если ставка неизвестна хотя бы для одного SKU, бот показывает подтверждённый
subtotal без полной прибыли и маржи. После явного `Обновить источники` новые
значения попадут только в сохранённую новую ревизию или копию; исходная версия
останется неизменной. Старые планы не получают текущие поставки автоматически.
Сравнение и CSV/JSON используют зафиксированный источник и показывают его метод
и полноту.

В карточке плана откройте `Готовность плана`, чтобы отдельно увидеть статус
расчёта, исторические допущения и наличие сверки с фактом. Экран ведёт прямо
к одному пропущенному полю или количеству. Количество `0` означает
подтверждённое отсутствие продаж; неизвестное значение остаётся неизвестным.
Исправление количества сначала показывается в предпросмотре и попадает в
новую ревизию только после подтверждения.

`Сравнить план с фактом` строит одну ограниченную finalized-сверку для точных
SKU выбранного плана и того же периода. Фактическое количество показывается
как подтверждённое только при точном источнике успешных единиц. Выручка плана
и факта сопоставляется отдельно от баллов за скидки; двухчастный мост — это
арифметика, а не доказательство, что изменение цены вызвало изменение продаж.
При несовпадающем охвате рекламы, внешних расходов или Return COGS бот не
вычитает фактическую прибыль SKU-группы из прибыли плана. Детали и CSV/JSON
читают один снимок и не обновляют Ozon. По истечении его 10 минут выберите
`Обновить факт`, чтобы получить новый снимок.

### Сравнение и выгрузка сохранённых вариантов

В `📚 Мои планы` откройте сравнение и выберите две сохранённые версии в рамках
текущего магазина. Бот перечислит изменения цены, себестоимости, рекламы,
баллов, расходов и объёма. Дельта выручки, прибыли и маржи появляется только
для совместимых периода, состава SKU, налоговой политики и версии расчёта;
маржа сравнивается в процентных пунктах. При несовместимости вы всё равно
увидите различия введённых значений, но итоговая денежная дельта будет скрыта.
Исторические версии не обновляются и не запрашивают Ozon.

Из сохранённого снимка можно выгрузить план, лимит рекламы, план объёма продаж
или сравнение в CSV/JSON. Файл содержит ту же проекцию и статусы, что показаны
на экране; неизвестные значения остаются пустыми с причиной, а не превращаются
в ноль. Это пользовательские отчёты текущего владельца и магазина, отдельно
от обезличенной технической диагностики.

## Обзор товаров и пакетный план

Откройте `🧭 Обзор товаров`, чтобы посмотреть решения и пробелы данных по
товарам в текущем магазине. Фильтры, страницы и выгрузки используют один
снимок. Чтобы собрать пакет, откройте карточку каждого нужного товара и
нажмите `Добавить в план цен`; выберите от 2 до 10 товаров этого магазина,
затем нажмите `🧮 План цен` и задайте целевую маржу.

Если строка неполная, откройте её меню `Изменить` и укажите отсутствующее
значение. Это ручное допущение только текущего пакетного плана; оно не
сохраняется как себестоимость магазина и не отправляется в Ozon. Далее можно
открыть чувствительность для строки, задать 3–7 абсолютных значений одной
оси или построить матрицу двух осей. Кнопки CSV/JSON выгружают весь снимок
плана или чувствительности. Эти расчёты описывают одну успешную продажу и не
прогнозируют спрос или общую прибыль магазина.

## Text commands

- `/start` — setup/main menu;
- `/help` — in-bot guide;
- `/memory` — saved facts;
- `/ozon_connect CLIENT_ID API_KEY` — connect a seller account;
- `/ozon_status` — connection status;
- `/ozon_disconnect` — remove the locally stored API key;
- `/costsku SKU AMOUNT` — technical current-cost fallback; normal users should
  prefer the guided `Себестоимость` button.

## Free-text examples

- `запомни цена sky = 1290`
- `прибыль с 01.08.2026 по 31.08.2026`
- `SKU 123: себестоимость 450 ₽ с 01.01.2026`
- `SKU 111 и SKU 222 — один товар`

Historical cost requires an explicit effective date. Product identity and cost
are separate facts. Unknown financial data is never converted to zero or false.
Ozon access remains strictly read-only, and API keys are never echoed.
