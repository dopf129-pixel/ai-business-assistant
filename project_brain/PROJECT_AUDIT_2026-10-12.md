## 2. Архитектура, подтверждённая кодом

Production entrypoint: `start_bot.ps1` → `app/telegram_api_bot.py` → `app/telegram_app_layer/telegram_api_bot.py` → `create_telegram_assistant()`.

`app/telegram_assistant_factory.py` собирает общий core, кнопку/адаптер/runner, прибыль за период, прибыль по SKU, эксперименты, себестоимость, onboarding, юнит-экономику, решения по товарам и возвраты. Это основной путь интеграции новых seller-facing функций.

`TelegramBotService._with_tenant()` формирует request-local scope пользователя и активного магазина. `app/api/ozon_client.py` разрешает credentials на каждый запрос, а `tenant_storage.py` выбирает локальную SQLite/JSON-папку магазина. Новые формы, результаты и кэши должны соблюдать этот scope.

Финансовый контур уже разделяет account-level денежный итог, идентичность товара, физическое количество продаж, историческую себестоимость, налог и доказательства Return COGS. Параллельный финансовый движок не требуется.

## 4. Конкретные находки и степень уверенности

1. **Подтверждено: повреждена обязательная документация.** `project_brain/CURRENT_STATE.md` и `project_brain/TEST_MAP.md` не декодируются как UTF-8 и содержат управляющие/бинарные байты. Оба имеют размер 90 059 байт. Последняя читаемая версия, найденная в истории этих файлов: `4d215dc`. Простое восстановление этой версии потеряет последующие сведения; нужна сверка с историей изменений и текущим кодом. `DECISIONS.md` читается. Корневой `README.md` пуст.
2. **Подтверждено: Windows persistence несовместим с текущим backend.** `terminal_safe_assistant_task_service.py` использует `fcntl.flock`; на Windows `fcntl=None`, а сохранение задач закрывается ошибкой. Фабрика использует этот сервис. POSIX-тесты дополнительно предполагают directory fsync и POSIX shutdown signals.
3. **Подтверждено: стандартная проверка неполная.** `pytest.ini` задаёт только `tests`; CI вызывает `python -m pytest -q`. В `app/tests` находятся 44 файла / 211 дополнительных проверок финансов, SKU, COGS и Telegram. Их явное выполнение обнаружило 35 падений. Ещё 90 корневых `test_*.py` относятся к старому контуру; их герметичность и назначение отдельно не проверены.
4. **Подтверждено: drift себестоимости.** Код и CSV задают первой стоимости `date.min` (`0001-01-01`) с source `SELLER_CONFIRMED_INITIAL_HISTORY*`; `docs/guided-cost-onboarding.md` описывает первую дату как сегодня. Старые тесты ожидают сегодняшнюю дату. Владелец 12.10.2026 выбрал правило: предлагать дату действия, а всю историю применять только после отдельного подтверждения. Это решение включено в P02; существующие версии автоматически не переписываются.
5. **Подтверждён структурный риск: CSV может сохраниться частично.** `SellerCostTableService.import_csv()` проверяет строки, затем вызывает recorder по одной строке. Общей транзакции импорта нет. При исключении Telegram-адаптер сообщает «Изменений не применено», хотя ранее записанные строки могут сохраниться. Ошибку записи второй строки следует воспроизвести отдельной фикстурой.
6. **Подтверждён структурный риск: незавершённая форма и смена магазина.** Pending себестоимости индексируется user ID; команда `ozon_store:*` обрабатывается до seller-cost adapter и его `clear_pending()`. Требуется сквозная проверка выбора в A → переключения в B → ввода значения. Чужая запись не должна попасть в B.
7. **Подтверждено: report слишком подробен по умолчанию.** Экспериментальный `_render()` выводит основную таблицу вместе с длинными пояснениями/диагностикой. Splitting уже работает; нужен отдельный компактный основной ответ и подробности по запросу.
8. **Подтверждено: источники количеств имеют разные определения.** Analytics, отменённые заказы периода и возвраты со сменой статуса — разные множества. Их отношения нельзя выдавать за сопоставимый процент отмен/возвратов без проверки знаменателя и дат.
9. **Подтверждено: Analytics ограничен одной страницей.** `_load_analytics()` возвращает INCOMPLETE при достижении лимита. Operational fallback ограничен бюджетами и правильно сохраняет unknown при неполной выборке; причины недоступности недостаточно различимы пользователю.
10. **Подтверждено: long-running watchdog не задаёт deadline.** `_run_sync_with_stall_notice()` продолжает ждать worker и показывать heartbeat. Проверки deduplication, бюджета optional reads и устаревшего результата необходимы до заявления о предсказуемом времени расчёта.
11. **Гипотезы требуют проверки.** Не каждое падение теста является ошибкой runtime: среди `app/tests` есть устаревшие создание объекта через `__new__`, ожидания старых кодов и старых сообщений. Ошибки физических количеств, временной себестоимости, SKU scope и final Return COGS следует разбирать независимо от текста сообщений.

## 6. Источники и ограничения исследования

Прочитаны AGENTS, архитектура, решения, ROADMAP, доступные handoff/status/verification-документы; обязательные повреждённые файлы сопоставлены с последней читаемой исторической версией. Изучены production factories, transport, financial/reporting services, cost/expense/tenant paths и соответствующие тесты. Предоставленные правила и шаблон Vector Core использованы как образец структуры задания; регламенты другого проекта не заменяют AGENTS этого репозитория и действующие поручения владельца.

Августовские контрольные деньги в ТЗ предоставлены пользователем и его сверкой XLSX в диалоге. В этом аудите XLSX заново не суммировался. Живые API-ответы также не запрашивались.

Попытка открыть официальные порталы Ozon через web-инструмент не позволила получить схемы (redirect/access errors). Поэтому новые поля отмен, возвратов или комиссии не объявляются подтверждёнными документацией. Luna должна привязать новые API-контракты к доступной официальной схеме и обезличенному реальному ответу.
