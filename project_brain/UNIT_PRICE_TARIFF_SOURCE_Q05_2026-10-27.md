# Q05 — подтверждённый источник комиссии и границы его применимости

Дата проверки: 27.10.2026.

## Проверенные первичные источники

- Официальный [Seller API FAQ Ozon](https://dev.ozon.ru/start/257-FAQ-spravochnik-oshibok-i-sposoby-ikh-resheniia) на вопрос о комиссии до установки цены отвечает, что процент комиссии по товару можно узнать методом `ProductAPI_GetProductInfoPricesV4`. FAQ подтверждает чтение процента комиссии для товара, но не описывает тарификацию для гипотетической цены.
- Справка операции: [ProductAPI_GetProductInfoPricesV4](https://docs.ozon.ru/api/seller/#operation/ProductAPI_GetProductInfoPricesV4). Справка динамическая; доступная текстовая версия не подтвердила передачу произвольной цены продавца, историю ставок или полные интервалы тарифа.
- Текущий клиент проекта использует `POST /v5/product/info/prices` с фильтром по `product_id`/`offer_id`; существующий `CurrentProductEconomicsSource` читает `commissions.sales_percent_fbo` и связывает эту ставку с полученной текущей ценой продавца. Вызывается существующая read-only операция один раз при явном обновлении сценария.

## Вывод о применимости

Подтверждённый результат ограничен текущей ценой конкретного товара, FBO и временем снимка. Проверенные материалы не подтверждают тарифную сетку по цене, применение будущих цен, изменение ставок по регионам/складам/датам или способ рассчитать ставку на соседнем диапазоне. Поэтому источник не считается полным для произвольного планирования цены. Это не означает, что отдельного закрытого или доступного в кабинете тарифа у Ozon не существует; только его API-контракт здесь не подтверждён.

Старые общие проценты и примеры 14%/20% не используются. Ни одна ставка не подставляется для цены, отличной от точки текущего снимка.

## Реализация Q05

Добавлен `UnitPriceTariffSource`: чистый адаптер принимает уже сформированный снимок `UnitPriceScenarioSource`, без новых запросов и без записи в хранилище. Он проверяет tenant/store/SKU identity, FBO, происхождение и полноту current price/commission, точность цены в копейках, корректность ставки, совпадение timestamp полей и свежий snapshot ID. Если доказательств недостаточно, тарифная точка отсутствует.

При валидном снимке адаптер формирует ephemeral `CURRENT_PRICE_POINT`, действующий только на точную текущую цену и календарную дату снимка. Одновременно всегда возвращает `RANGE_SOURCE_UNAVAILABLE` и `HYPOTHETICAL_PRICE_RANGE_NOT_CONFIRMED`. Для других цен расчёт должен продолжаться только после явного выбора сохранённого ручного профиля (Q06–Q07); текущий адаптер сам такую ставку не угадывает.

- `tests/test_unit_price_tariff_source.py`, `tests/test_unit_price_tariff_resolver.py`, `tests/test_unit_price_scenario_source.py` и `tests/test_current_product_economics_source.py`, Windows/Python 3.12.10, isolated temp/storage, dotenv/cache disabled, live credentials removed: **88 passed in 1.47s**.

Проверены точная точка и соседняя копейка, неизвестный произвольный диапазон, отсутствующая/некорректная ставка, нулевая подтверждённая ставка, несогласованный timestamp, FBS, чужой tenant, malformed completeness, неизменность input snapshot и безопасный отказ без исключения.

- Первый focused run имел **6 failed / 42 passed** из-за синтетической строки tenant scope с неверным разделителем. Фикстура исправлена по `split_store_tenant_scope`; final run выше зелёный.
