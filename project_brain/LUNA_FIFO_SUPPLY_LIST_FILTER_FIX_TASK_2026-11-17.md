# ТЗ Luna: исправить запрос списка поставок FIFO

Дата: 17.11.2026. Тип: небольшое исправление существующего функционала.

## Цель и подтверждённая причина

Владелец сохраняет новую себестоимость партии и нажимает «Обновить поставки». Бот выполняет один HTTP-запрос, получает отказ и показывает общее «источник временно недоступен» без найденных заявок. Это не доказательство отсутствия поставок.

17.11.2026 выполнен один диагностический запрос только чтения с теми же параметрами:

```http
POST https://api-seller.ozon.ru/v3/supply-order/list
```

```json
{
  "filter": {
    "states": [
      "DATA_FILLING", "READY_TO_SUPPLY", "ACCEPTED_AT_SUPPLY_WAREHOUSE",
      "IN_TRANSIT", "ACCEPTANCE_AT_STORAGE_WAREHOUSE",
      "REPORTS_CONFIRMATION_AWAITING", "REPORT_REJECTED", "COMPLETED",
      "REJECTED_AT_SUPPLY_WAREHOUSE", "CANCELLED", "OVERDUE", "UNSPECIFIED"
    ]
  },
  "limit": 10,
  "sort_by": "ORDER_CREATION",
  "sort_dir": "ASC"
}
```

Ответ: HTTP **400**, `code="3"`, безопасный текст ошибки:

```text
Request validation error: invalid SupplyOrderListRequest.Filter: embedded message failed validation | caused by: invalid SupplyOrderListRequest_Filter.States[11]: value must not be in list [0]
```

Индекс 11 соответствует `UNSPECIFIED`. Служебное нулевое значение enum запрещено именно в фильтре списка. Наличие этого значения в описании enum ответа не разрешает отправлять его в `filter.states`.

Исправление не требует выбора новой бизнес-логики. Не проектировать альтернативный учёт партий и не менять количество товара вручную.

## FLF03 — понятная безопасная диагностика HTTP 400

1.    > Ozon отклонил параметры запроса списка поставок (HTTP 400). Требуется проверка запроса бота; результат не означает отсутствие поставок.

5. Добавить регрессию: синтетический HTTP 400 с маркерами секретов/идентификаторов показывает безопасную причину и не выводит маркеры; 429/таймаут не маркируются как неверные параметры. Использовать существующие тесты и помощники, не создавать отдельный диагностический слой.
