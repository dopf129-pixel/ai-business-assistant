## Непересекающиеся области проверки

1. **Прибыль магазина** сравнивает суммы одного store и периода. Производные категории рекламы, логистики, комиссии и размещения раскрывают уже учтённые net-начисления; они не добавляются к итогам повторно.
2. **Экономика SKU на единицу** использует только точные SKU-суммы/источники. Общие расходы не распределяются по товарам без утверждённого правила и объяснённой базы.
3. **План цены** применяет явно замороженные сценарные входы, текущий `TaxService` и подтверждённые оценки расходов. Это не факт продаж.
4. **Return COGS** допускает себестоимость только после имеющегося authorization/commit процесса. Обычная диагностика отчётов остаётся read-only.

## Статусы сравнения

- `MATCH` — один источник/период/зерно и совпадение в заданном округлении.
- `EXPLAINED_DIFFERENCE` — измеренное расхождение объяснено полем, временем или зерном другого источника.
- `UNRESOLVED` — сопоставимый источник есть, расхождение доказано, причины нет.
- `NOT_COMPARABLE` — различаются дата-база, единица, scope или зерно; сумма не подгоняется.
- `EVIDENCE_REQUIRED` — источник/покрытие отсутствует или чтение неполное.

## Приёмка матрицы

Матрица не утверждает, что конкретный отчёт содержит каждую метрику. Для каждого реального сравнения нужно записать filename fingerprint в локальном manifest, период по содержимому, source/date basis, размер выборки/зерно и status. Сырые строки, SKU, номера заказов/поставок и данные продавца остаются вне Git. Примеры, которые уже были сообщены владельцем, остаются историческими ориентирами, пока A01/A04 не подтвердят их на неизменённом исходнике.

## A02 — границы реализованного comparator

- Единственный XLSX профиль: `ozon_accruals_xlsx_v1` (лист `Начисления`, заголовок в строке 2, обязательные `Дата начисления` и `Сумма итого, руб.`). Профиль суммирует signed строки, включая корректировки и возвраты, через `Decimal`; одинаковый ID начисления не дедуплицируется.
- Эталон сравнивает только `net_accrual` с одноимённой метрикой из существующего `owner_analytics_export/period_profit`. Комиссия, продажи по SKU, заказы, отмены, возвраты и Return COGS остаются для профильных этапов.
- Пользователь указывает период по видимому периоду отчёта, подтверждает полноту выгрузки и задаёт одинаковый нейтральный alias магазина. Alias — ручная защита от случайного смешивания, не проверенная Ozon-идентичность. SKU-фильтр не сравнивается со store-level экспортом; разные размерности дают `NOT_COMPARABLE`.
- Revision копируется из сохранённого экспорта или указывается явно. Старый экспорт без этой метки остаётся `UNAVAILABLE`; текущий git HEAD автоматически не подставляется.
- Локальный августовский файл прочитан read-only: 38 864 строки, 0 строк с некорректной датой. Денежные значения/ID/SKU исходника не записывались в репозиторий.
- Запуск: `python daily_use_reconcile.py --help`; XLSX-профилю нужен dev-пакет OpenPyXL. `reference` создаёт нормализованный локальный эталон, `snapshot` проецирует сохранённый JSON экспорт, `compare` сравнивает два локальных JSON.

## A03 — проверенное существующее поведение и остаточные границы

- Подтверждённая августовская комиссия из actual realization API, включая продажу и возврат комиссии, покрыта существующими regressions; финансовый source fallback отдельно остаётся provisional. Нулевой или неполный monthly realization не становится подтверждённым нулём.
- Явное `Размещение на складе` и неизвестные финансовые категории имеют отдельные tests. Подтипы рекламы/кросс-докинга/обратной логистики относятся к разложению начислений и не добавляются к прибыли повторно.
- Cross-docking tests покрывают signed корректировки, старую корректировку в дате начисления, обратную логистику, exact SKU/shared scope, принятые единицы, Moscow date boundary и incomplete pagination.
- Seller/Analytics tests различают отменённые отправления, тип возврата и quantity, обеспечивают уникальные ID/полные страницы и оставляют missing metrics неизвестными. Return COGS остаётся gated существующей авторизацией и commit-процессом.
- Новый трёх-SKU тест относится к плановой mix-модели: проверяет независимые ставки комиссии/рекламы, нулевой объём и partial при отсутствующей себестоимости положительного объёма. Он не заменяет сверку фактических SKU продаж/COGS из Ozon.
- Результаты на этой ветке: 94 теста в core finance/store/cross-docking профиле и 90 тестов в product/unit/planning профиле прошли. Поддержанные системой временные тесты, которые требуют ACL-недоступного `tmp_path`/`TemporaryDirectory`, ждут exact-head CI.
