# Telegram UX калькулятора цены и прибыли на единицу (Q25)

Дата: 27.10.2026
Статус: VERIFIED
Классификация: Architecture Review Required

## Вход и навигация

- В главном меню есть отдельная кнопка «Подобрать цену по прибыли/шт.». Старый пункт «Юнит-экономика товаров» и его переходы сохранены.
- Help и примеры объясняют: калькулятор плановый, работает только для FBO; пользователь задаёт цену продавца/себестоимость/рекламу, а не подтверждённую комиссию может указать вручную; бот не меняет цену или рекламу в кабинете.
- Обратная навигация сохраняет текущую версию сценария; детализация открывается read-only callback, привязанным к owner/store/scenario version.

## Результат

- Короткая карточка выдвигает прибыль в ₽/шт. и маржу, показывает товар/SKU, магазин, схему, цену продавца, себестоимость, комиссию и её основание, рекламный сценарий, кросс-докинг, сравнение с текущей ценой и ограничения.
- Неизвестная ставка, недостающий ввод и устаревший источник обозначаются явно; прибыль при неполном расчёте не показывается.
- «Подробности расчёта» раскрывает полную прежнюю детализацию: комиссию в рублях, логистику, последнюю милю, эквайринг, рекламу, баллы, кросс-докинг, налоговую базу, налог и источники. Кнопка «Краткий итог» возвращает в исходный scenario version.
- Сохранённый рейтинг включает точные owner-scoped магазин/SKU/product/offer и схему продажи. Raw source IDs и внешние operation IDs не добавлялись.
- Общий UTF-16 splitter и отправка длинного ответа с клавиатурой на последнем сегменте переиспользуются без изменения.

## Проверки

- Focused Windows/Python 3.12 UX profile: **59 passed in 1.88s**.
- Связанный Q16–Q25 Windows/Python 3.12 profile, 32 test targets: **495 passed in 12.46s**.
- Первый linked запуск обнаружил две утраты подсказок в сокращённом формате: stale source и отсутствие себестоимости. Обе исправлены; финальный повтор прошёл без failures.
- Только synthetic/test storage; live Telegram/Ozon, owner DB и реальный бот не запускались. `data/*.json` не менялись.

## Архитектура

Новый service, API source или persistence contract не вводились. Изменены существующие Telegram keyboard/help/result views; финансовая формула и canonical calculation не менялись. `DECISIONS.md` не менялся.
