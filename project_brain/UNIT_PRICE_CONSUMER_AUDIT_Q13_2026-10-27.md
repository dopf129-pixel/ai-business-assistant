# Q13 — аудит потребителей цены и тарифа

Дата: 2026-10-27
Статус: VERIFIED
Классификация: Architecture Review Required — расширены существующие calculator, batch, tariff snapshot и owner export contracts.

## Объём

Сверены все доступные пути, которые рассчитывают или повторно показывают комиссию при изменении цены: single-price target/options/grid/DRR/ad cap, sensitivity, batch plan/edit/replan/ad-cap, saved-plan restore, sales mix и owner exports.

## Результат аудита

| Путь | Результат |
|---|---|
| Single-price target, варианты, сетка, ДРР и лимит рекламы | Используют разрешение комиссии по цене-кандидату из одного frozen snapshot. Непокрытая цена, конфликт и устаревший источник не получают числовую комиссию. Перед локальным применением результат сверяется canonical forward. |
| Sensitivity | Каждая цена разрешается независимо по замороженным диапазонам; точка без диапазона применима только к точной цене. Неизвестные ячейки остаются неизвестными. |
| Batch edit/replan/ad cap | План несёт tariff snapshot; ручная ставка для новой цены становится точечным override; tariff provenance отображается в лимите рекламы. Не используется комиссия, рассчитанная для другой цены. |
| Saved-plan restore / sales mix | Восстановление проверяет tenant identity и сохраняет исторический tariff snapshot. Sales mix сообщает, что итог использует сохранённую цену и не гарантирует групповую маржу при будущих ценах. |
| Owner exports | Batch, saved-plan, ad-cap, sales-mix и sensitivity выгружают нормализованную ставку, источник, scope, status/reason и базу цены/даты. Экспорт не утверждает, что историческая граница тарифа доказывает ставку для нового candidate; owner IDs не добавляются. |
| Legacy планы/режимы | Старые point-only или legacy ставки допустимы только на исходной сохранённой цене. Явные fixed-rate assumptions остаются отдельным режимом и не маскируются подтверждённым профилем. |

## Изменённые контракты и тесты

- `UnitPriceTariffSnapshotAdapter` добавляет точечный manual override поверх frozen профиля и нормализует owner/user identity при проверке scope.
- Tariff profile runtime разрешает сценарий без сетевого обновления, привязывает его к owner/store/SKU и использует только свежий источник либо локальные подтверждённые профили.
- Sensitivity, batch planner, Telegram calculator/batch/sensitivity и owner exports используют общую тарифную основу; изменения профиля не переписывают замороженные сохранённые планы.
- Добавлены регрессии по диапазонной комиссии на каждой цене, gap/unknown, legacy точному тарифу, пакетному редактированию, сохранённому плану и согласованности полей owner export.
