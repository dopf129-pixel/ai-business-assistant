# W34 — руководство владельца и приёмка одного SKU (2026-10-29)

## Текущий статус продукта

Telegram интерфейс и offline lifecycle можно проверить на синтетическом снимке. Полный обычный запуск владельцем пока недоступен: приложение не формирует 56-дневный снимок расходов из источников. Если готового полного снимка нет, мастер обязан остановиться. Также Telegram flow пока создаёт только baseline; отдельного пользовательского шага для запуска candidate-фазы ещё нет. Не меняйте цену специально ради этого мастера, пока оба ограничения не закрыты.

Для проверки действительного пользовательского результата используйте только собственный SKU и локальный магазин. Этот документ описывает кнопки и действия, которые реально есть сейчас, и отдельно отмечает, где путь заканчивается.

## Доступный экран и условный путь

1. Откройте в боте «Юнит-экономика» → «🧪 Эксперименты цен» → «➕ Новый эксперимент».
2. Выберите активный сохранённый план и SKU. Мастер связывает его с текущими owner/store и точной ревизией плана.
3. Если для этого SKU нет сохранённого полного снимка ровно за 56 завершённых локальных дней, появится сообщение: «нет полного снимка расходов за 56 завершённых дней… автоматический сбор такого базового снимка пока не подключён». На этом остановитесь: не вводите числа вместо неизвестных расходов, не меняйте файлы базы и не передавайте API-ключи.
4. Если полный снимок уже подготовлен внутренним тестовым/интеграционным путём, выберите его строку `56 дней · дата — дата`. Он должен быть COMPLETE, иметь совпадающие SKU и часовой пояс. Partial/unknown снимок не предлагается.
5. Введите от 2 до 10 уникальных цен продавца через `;`, например `95; 99,90; 105`. Это только заданные владельцем кандидаты; модель не прогнозирует спрос.
6. Введите фактическую базовую цену и локальное время её установки, например `100; 2026-10-29 12:00`. Просмотрите период и нажмите «✅ Подтверждаю и начать» либо «Отмена». Подтверждение — заявление владельца, не доказательство истории цены Ozon. Бот не меняет цену и не вызывает Ozon API.
7. После активации откройте карточку из истории. Доступны фазы/результаты, «🔎 Сохранённые исходные данные», «📜 История версий», «⬇️ Выгрузить историю» и обновление карточки. Экспорт выдаёт JSON/CSV только сохранённой истории и не обновляет источники. Для активной связанной observation карточка может показать «📈 Сбор метрик».
8. Кнопки запуска candidate-фазы в текущем Telegram runtime нет. Нельзя считать базовый этап завершённым A/B-сравнением; дождитесь следующего релиза с candidate flow.

## Недостающие, частичные и исправленные источники

- **Источник отсутствует:** мастер прекращает setup без создания эксперимента. Перепроверьте, что выбран правильный store/SKU и что сохранённый план активен. Если снимка всё ещё нет, это не действие владельца — требуется подключение provider-specific source adapter разработчиком.
- **Источник частичный/неизвестный:** он не принимается как полный. Не считайте пустое значение нулём и не запускайте фазу на его основании. Сохраните точный диагностический код/текст без токенов, ключей и персональных данных.
- **Поздняя корректировка:** текущие снимки immutable. Корректирующую запись нужно будет загрузить через утверждённый adapter как новый exact snapshot/revision; предыдущий experiment и его экспорт должны остаться неизменными. Сейчас в Telegram нет импорта/кнопки исправления источников, поэтому вручную редактировать SQLite/данные не следует.
- **Повторная попытка:** после появления source integration создайте новый снимок, повторно откройте мастер и проверьте даты, часовой пояс, SKU, покрытие и status. Не перепривязывайте старый эксперимент к новым данным без новой revision.
- Платные отчёты и передача API credentials для локальной проверки не нужны.

## Полностью offline synthetic acceptance

Пример создаёт изолированную временную БД, один synthetic SKU `sku-1`, сохранённый план с ценой 100 ₽ и полную synthetic reference snapshot. Он проходит owner-confirm baseline и проверяет, что обычная цена/время остаются подтверждением владельца. Реальных товаров, ключей, платной подписки, Ozon API, Telegram API или запущенного бота тест не использует.

Из корня репозитория, после установки обычных `requirements-dev.txt`:

```powershell
$env:PYTHON_DOTENV_DISABLED = '1'
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = '1'
$env:PYTHONPATH = 'app;tests'
$env:AI_ASSISTANT_DATA_DIR = Join-Path $env:TEMP ('unit-economics-w34-' + [guid]::NewGuid().ToString('N'))
$python = '.\.venv\Scripts\python.exe'
if (-not (Test-Path -LiteralPath $python)) { throw 'Сначала создайте/активируйте проектное .venv с requirements-dev.txt.' }
$tzdataRoot = Join-Path $env:LOCALAPPDATA 'Programs\Python'
$tzdataPath = Get-ChildItem -LiteralPath $tzdataRoot -Directory -ErrorAction SilentlyContinue | ForEach-Object { Join-Path $_.FullName 'Lib\site-packages\tzdata\zoneinfo' } | Where-Object { Test-Path -LiteralPath $_ } | Select-Object -First 1
if ($tzdataPath) { $env:PYTHONTZPATH = $tzdataPath }
& $python -m pytest -q tests/test_telegram_unit_economics_experiment_runtime.py -k 'guided_wizard_creates_and_activates_owner_confirmed_baseline or wizard_blocks_when_no_full_reference_snapshot_exists or invalid_candidate_prices_keep_wizard_draft_open'
```

Ожидается 3 passing tests. Если Windows не имеет system timezone database и не установлен пакет `tzdata`, скрипт подключает уже установленную локальную IANA базу; сеть не нужна. Отдельный экспортный offline case можно проверить фильтром `-k experiment_history_export`; он формирует JSON/CSV из того же временного хранилища и проверяет privacy/quota/store scope.

## Что нужно для реальной приёмки владельцем

Инженерная проверка W31–W33 подтверждает только обработку подготовленных synthetic/persisted записей. До реального испытания одного SKU нужны: автоматическое формирование полного 56-day source snapshot и пользовательский путь создания/подтверждения candidate-фазы. После их реализации владелец сможет проверить один SKU на sandbox/test SKU, сверить источник каждой строки, выгрузить историю и подтвердить отсутствие price mutation.
