# W34 — руководство владельца и приёмка одного SKU (2026-10-29)

## Текущий статус продукта

После remediation R1–R5 Telegram интерфейс содержит действия для полного пользовательского сценария: сбор 56-дневного reference snapshot, baseline и candidate фазы, сбор/оценка данных, сравнение и запись решения владельца. Это локально проверено синтетическими источниками; точный новый PR SHA ещё должен пройти CI и повторный review. Проверка владельцем на реальном магазине остаётся pending.

Сначала обновите бот до ревью-исправленной версии после её слияния. До проверки источников на своём SKU не используйте модельный результат как подтверждение будущей прибыли. Бот не устанавливает цены.

## Путь владельца в Telegram

1. Откройте в боте «Юнит-экономика» → «🧪 Эксперименты цен» → «➕ Новый эксперимент».
2. Выберите активный сохранённый план и SKU. Мастер связывает его с текущими owner/store и точной ревизией плана.
3. Если полного снимка для выбранного SKU нет, нажмите «🔄 Собрать снимок за 56 дней». Бот только читает финансовые начисления и FBO количество; CPC и история цены не запрашиваются. Неполный ответ не сохраняется как COMPLETE; при частичном результате прочитайте причину и повторите сбор позже.
4. Проверьте сохранённый снимок `56 дней · дата — дата` и выберите его. Снимок должен относиться к выбранному SKU и часовому поясу.
5. Введите от 2 до 10 уникальных цен продавца через `;`, например `95; 99,90; 105`. Это сценарные кандидаты, модель не прогнозирует спрос.
6. Введите базовую фактическую цену и локальное время установки, например `100; 2026-10-29 12:00`. Подтвердите условия контроля или отметьте, что они неизвестны/менялись; затем отдельно подтвердите старт baseline-фазы. Подтверждение — заявление владельца, не история цены Ozon.
7. В карточке baseline откройте фазу, нажмите «Собрать данные Ozon», затем «Оценить зрелость данных». Завершить фазу можно только после READY. Время дозревания учитывает полные локальные дни и минимальный размер выборки.
8. После завершения baseline выберите кнопку тестирования нужной candidate-цены. Введите её фактическое время установки, отметьте контрольные условия и подтвердите запуск. Для candidate повторите сбор, оценку и завершение.
9. После завершения candidate нажмите «Сравнить с базовой фазой». Просмотрите ограничения и сохраните решение владельца. Решение фиксирует рекомендацию, но бот не меняет цену в Ozon.
10. В карточке остаются «🔎 Сохранённые исходные данные», «📜 История версий», «⬇️ Выгрузить историю» и обновление; экспорт не обновляет источники и не пересчитывает результат.

## Недостающие, частичные и исправленные источники

- **Источник отсутствует:** проверьте store/SKU и активный сохранённый план, затем запустите сбор 56-дневного снимка. Если источник недоступен, повторите позже; неизвестные значения не вводятся вручную как нули.
- **Источник частичный/неизвестный:** он не принимается как полный. Не считайте пустое значение нулём и не запускайте фазу на его основании. Сохраните точный диагностический код/текст без токенов, ключей и персональных данных.
- **Поздняя корректировка:** снимки immutable. Повторный сбор создаёт новую версию данных; прежние результаты не перезаписываются. Повторно оцените актуальную фазу перед завершением/сравнением.
- **Повторная попытка:** кнопка «Повторить сбор» доступна после частичного reference-ответа. После новой phase collection выполните новую оценку зрелости; старый result revision остаётся в истории.
- Платные отчёты и передача API credentials для локальной проверки не нужны.

## Полностью offline synthetic acceptance

Пример создаёт изолированную временную БД, один synthetic SKU `sku-1`, сохранённый план с ценой 100 ₽ и полную synthetic reference snapshot. Он проходит owner-confirm baseline и проверяет, что обычная цена/время остаются подтверждением владельца. Реальных товаров, ключей, платной подписки, Ozon API, Telegram API или запущенного бота тест не использует.

Из корня репозитория, после установки обычных `requirements-dev.txt`:

```powershell
$env:PYTHON_DOTENV_DISABLED = '1'
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = '1'
$env:PYTHONPATH = 'app;tests'
$env:AI_ASSISTANT_DATA_DIR = Join-Path $env:TEMP ('unit-economics-w34-' + [guid]::NewGuid().ToString('N'))
$python = '.\.venv\Scripts\python.exe'
if (-not (Test-Path -LiteralPath $python)) { throw 'Сначала создайте/активируйте проектное .venv с requirements-dev.txt.' }
$tzdataRoot = Join-Path $env:LOCALAPPDATA 'Programs\Python'
$tzdataPath = Get-ChildItem -LiteralPath $tzdataRoot -Directory -ErrorAction SilentlyContinue | ForEach-Object { Join-Path $_.FullName 'Lib\site-packages\tzdata\zoneinfo' } | Where-Object { Test-Path -LiteralPath $_ } | Select-Object -First 1
if ($tzdataPath) { $env:PYTHONTZPATH = $tzdataPath }
& $python -m pytest -q tests/test_telegram_unit_economics_experiment_runtime.py -k 'guided_wizard_creates_and_activates_owner_confirmed_baseline or wizard_blocks_when_no_full_reference_snapshot_exists or invalid_candidate_prices_keep_wizard_draft_open'
```

Ожидается 3 passing tests. Если Windows не имеет system timezone database и не установлен пакет `tzdata`, скрипт подключает уже установленную локальную IANA базу; сеть не нужна. Отдельный экспортный offline case можно проверить фильтром `-k experiment_history_export`; он формирует JSON/CSV из того же временного хранилища и проверяет privacy/quota/store scope.

## Проверка владельцем на одном SKU

Инженерный тест не подтверждает, что live-данные вашего магазина полны и классифицируются верно. На одном SKU проверьте диапазон 56 дней, количество FBO, финансовые компоненты, единицы и source status; затем сверяйте каждый phase window с отчётами Ozon. При UNKNOWN/PARTIAL не принимайте прибыль на единицу за подтверждённую. Экспортируйте историю и проверьте, что решение владельца сохранено, а цена в личном кабинете Ozon не менялась ботом.
