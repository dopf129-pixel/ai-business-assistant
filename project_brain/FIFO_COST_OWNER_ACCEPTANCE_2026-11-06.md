# Приёмка FIFO владельцем: безопасный план

Дата: 06.11.2026  
Результат сейчас: `USER_VALIDATION_PENDING`; фактический FIFO COGS: `SOURCE_BLOCKED`.

Этот файл — план для отдельной проверки владельцем после собственного обновления и запуска бота. В рамках разработки и CI живые запросы не выполняются. Никакие API-ключи, Client ID, `.env` или необезличенный JSON не нужны.

## Сначала проверить доступность сценария

1. Откройте в боте меню `Себестоимость`.
2. Нажмите `📚 FIFO · <товар>` у нужного SKU.
3. Проверьте магазин, offer/SKU, ревизию FIFO, остатки слоёв, статус источника и срез.
4. Если очередь не инициализирована, после обновления до сборки с review-fixes должны появиться два действия: задать старые партии или начать с нулевого остатка. Используйте первый путь, если где-либо остался товар. Нулевой путь — только при отсутствии товара дома, на FBS-складе и в пути; Ozon должен отдельно подтвердить нулевые FBO/reserved по точному SKU. Неполный источник должен завершиться отказом без записи.

Пользовательские сценарии начальных партий и нулевой начальной ставки подключены в ветке PR, но не подтверждены владельцем в живом боте. Проверка владельцем остаётся `USER_VALIDATION_PENDING`; текущий код нельзя считать установленным, пока бот не обновлён.

## Числа и признаки для сравнения, если карточка доступна

- выбран текущий магазин и ровно один SKU;
- явно отделены конечное известное количество и неизвестное количество открытой ставки;
- зарезервированные единицы не прибавлены к FBO повторно и не вычтены как продажи;
- частичная приёмка использует `fact_quantity`, а не `approved_quantity` автоматически;
- одна поставка с другим SKU не связывается с текущим товаром;
- переход старого товара домой → транзит → Ozon не создаёт повторный приход;
- неполная пагинация, конфликт, неизвестная дата/срез не выводятся как завершённый нулевой результат;
- плановый результат и фактическая периодная прибыль имеют разные маркировки и не смешиваются.

## Передача результата

Если хотите поделиться результатом, пришлите только обезличенный текст самого сообщения бота. Оставьте имена полей, типы, количества, суммы, даты и статусы полноты. Замените SKU/offer, название товара и ID поставки/акта на `SKU-A`, `Товар-A`, `SUPPLY-A`, `ACT-A`. Не копируйте API-ключ, Client ID, `.env`, URL с токенами или сырые ответы API.

Проверки синтетических фикстур подтверждают кодовые ветви, но не меняют `USER_VALIDATION_PENDING` и `SOURCE_BLOCKED`. После отдельного PR пользовательский начальный якорь, подтверждённый физический cutoff и все описанные ограничения проверяются снова.
