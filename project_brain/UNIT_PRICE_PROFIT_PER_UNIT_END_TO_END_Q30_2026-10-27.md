# Q30 — сквозные пользовательские сценарии выбора цены по прибыли с единицы

Дата: 27.10.2026
Статус: `BLOCKED_DECISION` — два новых сценария проверены; для третьего требуется ответ владельца.

## Проверенные сценарии

1. Подтверждённая текущая тарифная точка через production factory и публичные Telegram handlers. Используются синтетические read-only источники; сохранённый тарифный snapshot выгружается в JSON без повторного чтения источников.
2. Ручной тариф с двумя диапазонами, переключение магазина, отказ в чтении профиля из другого магазина, повторное создание production composition и восстановление тарифа из локальной БД; JSON export выполнен через публичный handler.
3. Существующий end-to-end сценарий Q24 повторно прошёл с текущим набором тестов: SKU → ручная комиссия → варианты цены/ДРР → сохранённый план → наблюдение → честный отказ в ранжировании неполных данных → возврат к планам и выбор следующей цены.

Проверка `tests/test_unit_price_profit_per_unit_end_to_end.py`: **3 passed in 1.32s** на Windows/Python 3.12. Все источники синтетические; live Ozon API и мутации через API не подключались. Q31 linked profile после тестовых изменений подтверждён отдельно.

## Открытый вопрос для завершения третьего сценария

Сейчас коллектор не подтверждает число успешных продаж: `ordered_units` из Analytics нельзя автоматически считать успешными продажами без надёжно согласованных отмен и возвратов. Модель Q19 поэтому корректно сохраняет `INSUFFICIENT_DATA`, а quality gate Q21 блокирует сравнение без подтверждённого знаменателя.

Для требуемого перехода `недостаточное наблюдение → допущение → доступная модель → сравнение` нужно решить, разрешать ли владельцу вручную задавать число успешных единиц. Если разрешить, это будет отдельное owner-entered допущение с отдельной provenance, сохранённой в immutable result и assumption signature; его нельзя выдавать за факт Analytics/Finance или за canonical observed profit. Сопоставление допускается только при одинаковом явном допущении во всех сравниваемых вариантах.

Бизнес-вопрос передан владельцу: разрешить ручное допущение количества успешных единиц для модельного результата с явной маркировкой и без статуса факта Ozon? До ответа production-контракт не расширять и результат не подменять нулём/заказанными единицами.
