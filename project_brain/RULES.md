# AI Development Rules


## General Principle


AI является помощником разработчика и работает только через установленную архитектуру.


Любое изменение должно сохранять:

- архитектуру
- тестируемость
- обратную совместимость


---

# Before Development


Перед началом любой задачи AI обязан:


1. Прочитать:

- ARCHITECTURE.md
- CURRENT_STATE.md
- RULES.md
- ROADMAP.md


2. Проверить:

- текущие тесты
- существующие сервисы
- зависимости


3. Сформировать план изменений.



---

# Development Process


Каждая новая функция проходит этапы:


## Step 1

Создать тест.


Пример:


tests/test_new_feature.py



## Step 2

Изменить минимальное количество файлов.



## Step 3

Запустить:


python -m pytest



## Step 4

Обновить документацию.



---

# Code Rules


## Services


Каждый сервис:

- отвечает только за свою область
- не содержит бизнес-логику другого сервиса
- получает зависимости через constructor injection


---

## Tests


Новый функционал = новый тест.


Запрещено:

- удалять тесты
- отключать проверки
- менять ожидаемый результат только ради прохождения теста


---

# Change Rules


Если меняется архитектура:


Обновить:

- ARCHITECTURE.md
- DECISIONS.md


---

# Documentation Rules


После каждого завершённого блока обновлять:


CURRENT_STATE.md

CHANGELOG.md

TEST_MAP.md



---

# Git Rules

код

тесты

документация

commit

# AI Behaviour


AI должен:


- сначала анализировать
- потом менять код
- объяснять причину изменения
- избегать больших замен без необходимости
